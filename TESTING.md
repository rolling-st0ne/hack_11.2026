Тесты покрывают CSV/D1-совместимое хранилище, API, ролевые проекции, 18 KPI, все фильтры, импорт, точные контрольные суммы, штат/смены, 4 недели прогноза, ошибки, аудит, идемпотентность, реальные пароли/сессии/CSRF, ограниченные токены, подтверждения, версии и откат. ## Границы

Worker smoke использует SQLite как D1-совместимый интерфейс; это не размещение в Cloudflare и не нагрузочный тест. Промышленный SSO и живые CRM/1С/HR не подключены и не требуются для синтетического MVP. Metabase и Docker — опциональные ветки; основной приёмочный путь использует `CONTOUR_BI=off`. Существующие тесты BI/Host также входят в общий набор; запуск отдельного контейнерного стенда описан в соответствующих документах.

На один каталог CSV допускается один API-процесс. Тесты используют временные каталоги и не сбрасывают рабочие решения. Устная защита перед жюри и промышленная приёмка не подменяются автоматическим отчётом; ответы для демонстрации подготовлены в DEMO.md и ARCHITECTURE.md.

## Docker Compose

Проверено 12 ноября 2026 на Docker Desktop (Linux ARM64):

- `docker compose up -d --build --wait` собирает образ, автоматически готовит хранилища и Metabase; приложение и Metabase достигают состояния healthy.
- Образ работает под UID 1000, не содержит локальные `.data/auth/ACCESS.txt` и отчёты аудита. Наружу опубликован только порт приложения; Metabase читает отдельный SQLite-том, без доступа к аккаунтам приложения.
- Реальный HTTP проверен через localhost и оба текущих LAN-адреса хоста. Другой физический клиент не использовался.
- `docker compose exec app node scripts/smoke-container.mjs prepare` проверил входы, запрет чужого подразделения, отказ неизвестному Host, закрытость `.data` и реальные результаты Metabase.
- После `docker compose down` и повторного `docker compose up -d --build --wait` команда `docker compose exec app node scripts/smoke-container.mjs verify` подтвердила сохранность бизнес-CSV, аккаунтов, записи аудита, ID/секретов Metabase и значений KPI. Тома не удалялись.
- `docker compose exec app node scripts/smoke-local.mjs` подтвердил REST-каталог, персональные токены, preview, запрет подтверждения агентом и отзыв токена. Изменения конфигурации не применялись.

Команды проверки оставляют обычные записи авторизации/предпросмотра в аудите и приватный файл контрольных хешей `.data/container-verification.json`. Бизнес-записи smoke не изменяет. Визуальная проверка интерфейса не входит в этот протокол.
