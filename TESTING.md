# Проверка MVP

Автоматизированные проверки: `npm test`. Они вызывают реальный общий API и SQLite-адаптер с изолированной in-memory базой, не изменяя демонстрационный стенд.

| Критерий | Проверка |
| --- | --- |
| УП-01 | 1 800 заказов, 360 клиентов и 800 обращений; все customerId/orderId валидны |
| УП-02 | 16 конечных числовых KPI с формулами, источниками и временем |
| УП-03 | Период/подразделение/продукт меняют выборку, KPI, chart и ресурс; сумма точек orders равна числу заказов |
| УП-04 | Создание, статусы и проверки сохраняются в состоянии и журнале; повтор создания не дублирует задачу |
| УП-05 | Руководитель получает только books; чтение/изменение чужого подразделения возвращает 403 и фиксируется |
| Прогноз | Четыре недели, спрос, мощность, дефицит и равенство gap = capacity − demand |
| Роли | Оператор не создаёт решения, не экспортирует и не получает финансовые KPI |
| Сбой | Mock-сбой даёт 503, состояние сохраняется; после восстановления работает тот же ключ |
| Повтор | Тот же Idempotency-Key даёт исходное решение; другое тело — 409; sourceEventId дедуплицируется с другим транспортным ключом |
| Сценарий | Сигнал → задача → in_progress → review → отрицательная проверка → успешная проверка → 24 фотокниги в исходных фактах |
| Валидация | Некорректный срок/переход отклоняется без изменения задачи; анонимный API даёт 401; inherited role key отклоняется |
| Origin | Запись с другого сайта даёт 403; отсутствующий ключ записи — 400 |

Ручная браузерная проверка выполняется на локальном стенде: загрузка, деталь сигнала, назначение и изменение решения, форма результата. Итоговые наблюдения и дополнительные результаты приведены в финальном сообщении.

Ограничения: автоматические тесты не проверяют настоящие внешние CRM/ERP/1С и SSO — их нет в MVP. Проверки SQLite/API не заменяют нагрузочное тестирование D1. Защита ролей действует в каждой демосессии, но переключатель ролей намеренно доступен всем посетителям частного демостенда.
