# Демонстрация за шесть минут

## Подготовка

Основной стенд с Metabase: из каталога приложения выполнить `APP_PORT=3310 docker compose -p fotoprint-presentation up -d --build --wait`. Открыть http://localhost:3310 или http://<LAN-IP сервера>:3310. Основное рабочее приложение и его тома остаются отдельными. Нужны Docker/Compose и заранее скачанные образы.

Пароли: `docker compose -p fotoprint-presentation exec app cat .data/auth/ACCESS.txt`. На подготовленном Mac личная копия сохранена в `.data/presentation/ACCESS.txt`. Выдать демонстратору executive и maxim; analyst нужен для вопросов. Пароли не показывать на проекторе и не публиковать. Смена роли — выход и новый вход.

Контрольный поставляемый набор создан 12 ноября 2026. Выбрать **06–12 ноября 2026**, все рынки/направления/продукты. В исходном срезе: **220 заказов, 81 563 BYN, 53 заказа на модерации**, доступен SIG-1042. Период 05–11 ноября не подходит для основного сценария: сигнал создан 12 ноября и корректно исключается фильтром.

Для репетиции в другой день: `npm run seed` обновляет только исходные fixtures и сохраняет резервную копию. Затем запустить новый Compose-проект с другим именем и свободным портом; существующие тома/решения не удалять. Выбрать неделю, заканчивающуюся новой датой генерации. Даты и контрольные суммы из этого документа тогда заменить фактическими; не выдавать их за постоянные значения.

Автономный резерв при отсутствии Docker/BI: `npm run demo:prepare`, затем `npm run demo:start` (Node ≥22.13, порт 3311). Создаётся отдельный свежий набор и персональные пароли, их пути печатаются без самих паролей. Metabase в этом режиме выключен, что явно объявляется аудитории. Повторный prepare создаёт новую репетицию и сохраняет прежние.

Весь показ занимает **6 минут, включая введение и переходы между слайдами и приложением**. Полные 10 слайдов — опора и резерв для вопросов; их не читать подряд сверх времени демо. Подробная памятка: [DEFENSE.md](submission/DEFENSE.md).

## Сценарий

| Время | Действие | Что видно |
|---|---|---|
| 0:00–0:40 | Коротко назвать проблему и персону; войти executive | Общий дашборд, 18 KPI, план/факт и статус |
| 0:40–1:40 | Период 06–12 ноября; выбрать срез, открыть выручку/заказы, затем вернуть все фильтры | Источник Metabase, формула, свежесть, история и связанные записи |
| 1:40–3:20 | Быстро показать прогноз мощности; открыть SIG-1042 → «Назначить решение»; заполнить влияние/причину/действие, назначить Михаила и срок; взять в работу | Смены и дефицит недели; решение с владельцем, сроком, приоритетом и историей |
| 3:20–4:20 | Отметить действие выполненным → «Отклонение осталось» → «Показатель восстановился»; обновить страницу | Первая проверка не закрывает; вторая закрывает по значению ≤30. Аудит и результат сохранены |
| 4:20–5:10 | Выйти, войти maxim; открыть в соседней вкладке `/api/bootstrap?department=books` того же стенда | Только photo; прямой чужой запрос — 403. Закрыть вкладку с JSON |
| 5:10–6:00 | Показать подготовленную схему/проверки и назвать ограничения, гипотезы пилота | Связь данных, права, отсутствие заявленного экономического эффекта; ответы на вопросы |

Аналитик и «Источники данных» — резерв после основного тайминга: войти analyst, показать качество и финансовую сверку; изменение решений недоступно.

## Короткая проверка ошибки

В новом решении измените действие, нажмите Escape и снова откройте ту же форму: черновик восстановится. При ошибке API он также сохраняется. В «Источниках данных» директор может скачать CSV, удалить обязательный productId и попробовать импорт: ошибка объясняет поле, исходный набор остаётся активным.

Основные действия доступны клавишами Tab/Shift+Tab, Enter/Space; в списках — стрелки, Home/End и Escape. Диалоги закрываются Escape с сохранением изменённого черновика. Кнопка темы переключает светлый/тёмный режим.
