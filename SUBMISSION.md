## Код с историей

[Актуальная ветка main](https://github.com/rolling-st0ne/hack_11.2026). Ветка `presentation-ready-2026-11-12` сохраняет предыдущий снимок релиза.

```sh
git clone https://github.com/rolling-st0ne/hack_11.2026.git
cd hack_11.2026
docker compose up -d --build --wait
```

Приложение находится в корне репозитория; в исходном рабочем каталоге автора — в fotoprint/. Репозиторий приватный: жюри нужен выданный доступ. Ранее подготовленные ZIP и Git bundle содержат снимок релиза; текущую версию следует брать из `main`.

## Готовый стенд

На подготовленном Mac единственный актуальный стенд: http://localhost:3310; с другого устройства — http://<LAN-IP Mac>:3310. Адрес хоста можно посмотреть через `npm run address` (для Docker использовать порт 3310).

Действующие пароли получить командой `docker compose exec app cat .data/auth/ACCESS.txt`. Старые локальные копии могут относиться к другому экземпляру. Эти файлы не входят в репозиторий/архив. Использовать executive и maxim; analyst — для вопросов. Не показывать пароли аудитории.

Для поставляемого набора выбрать **06–12 ноября 2026**: в нём виден SIG-1042. Перед показом возвращать все фильтры. Основной сценарий изменяет демоданные; повторная репетиция проводится на новом наборе по DEMO.md, не через удаление рабочих томов.

Без Docker/BI: `npm run demo:prepare`, затем `npm run demo:start`. Нужен Node.js ≥22.13, приложение на порту 3311; источник будет Filesystem. Это честно обозначенный резерв, а не показ отключённого BI как подключённого.

Остановка отдельного презентационного стенда: `docker compose -p fotoprint-presentation stop`. Не выполнять down -v: тома содержат историю показов.

## Что ещё проверяется человеком

Полная репетиция с секундомером на экране зала, распределение рассказа/управления и устные ответы жюри. Другой физический клиент и доступ внешнего аккаунта жюри к приватному GitHub не проверялись. Старый опубликованный Sites-демо не подменяет эту версию.
